2543 — One app: the terminal, documents and pages share one frame

Author: Claude (Opus 5.5) 0ba7dfd9 · Ticket #2543 · 2026-10-27 · Revision 2

Memo

I recommend that the terminal page's layout become the layout of the whole web app. Every page gets one left sidebar. Its top half holds the page links (Inbox, Board, Queue…). Its lower half holds the live agents and shells, the list that today exists only on the terminal page. The Agents page becomes the overview you reach by clicking the "Agents" heading. A terminal and a document become two focus views: they fill the space right of the sidebar. A document folds the sidebar away so you can read. The side panel on the right goes back to small things about what you are looking at: details, messages, a queue job, notes. Documents no longer open there.

The result is one sidebar and one top bar on every screen, both always in the same place. Getting from a terminal to Board and back is one click each way, as it is between any other two pages.

Sidebar
The single left column on every page. Top: "sm", the search box (⌘K), page links with their badges. Middle: Agents heading, then the live agents and shells grouped Needs you / Moving / Idle / Terminals. Bottom: usage meters, overnight moon, Settings. It folds to a thin strip with ⌘\ or a click on that strip.
Focus view
A page whose subject is one thing that wants the whole width: an agent's or shell's terminal, or a document.
Top bar
The 40-pixel bar above the main area. Left: what you are looking at (a page name, an agent's name and context ring, a document's title). Right: actions on it. Today's terminal page bar is the model.
Side panel
The resizable column on the right: an agent's details and message thread, a queue job, a ticket, Notes.

How it flows: one evening

You are watching far-2390 in its terminal. The sidebar shows Inbox 1. You click Inbox and read far-2419's question. You click far-2419 in the sidebar; its terminal opens, and you answer. Its message mentions the iteration 11 memo; you click the link, and the memo fills the screen with the sidebar folded. ⌘[ takes you back to far-2419's terminal, still connected and up to date. You click Queue to see whether the backtest finished, then far-2390 in the sidebar. You never leave the tab, and the sidebar never moves.

Why this design

The terminal page already had the right layout. Its left column is the list of agents; that list is the thing you navigate by. The old left navigation lists pages, and the old Agents page is a large version of the same agents list. Putting both lists in one column, pages above agents, gives a single place to go anywhere. Slack and Linear use this layout for the same reason: destinations and live items in one sidebar.

It fits. In the browser window from your bug screenshot (about 820 points tall), the page links, heading and meters take about 340 points, leaving room for eleven two-line agent rows before the list scrolls. Three rarely used pages move to a "More" menu to make that room.

Focus views stay immersive. The terminal keeps today's width and bar. A document gets the whole width, because reading is what you open it for, and the side panel is a poor place to read. Both keep one way back to everything: the sidebar, one click or ⌘\ away.

Cost. On Board and Queue the sidebar is wider than today's left column (15.5 rem against 9 rem, about 100 points), because it now holds agents. ⌘\ folds it on any page.

B. Frame and sidebar

  1. Frame. App() renders one grid on every page: sidebar | main | [side panel]. main is the top bar plus the page or focus view. There is no early return for the terminal page; .term-page stops being a position: fixed overlay and fills main. The terminal page's own Details/Notes column becomes the app's side panel (one side panel component for all pages, resizable and widenable as today's Panel). On the terminal view, agent:<id> for the current agent still renders details only (beside='terminal'), and the Notes pane keeps "Type into terminal".
  2. Width. Open: 15.5rem (today's switcher width). Folded: a 14px strip with today's .term-edge look; clicking it opens the sidebar. The fold control when open is the same strip on the sidebar's right edge.
  3. Contents, top to bottom.
    1. "sm" (navigates to /).
    2. Search box, label "Search or jump…", ⌘K hint; click opens the palette.
    3. Page links: Inbox, Board, Queue, Artifacts, Notes, with today's badges from badges(). Queue's row also shows <running> run · <waiting> (amber when a job has waited 30 minutes), replacing the top bar meter. The current page is highlighted.
    4. Agents heading (D.1) and the session list (D.2). This part alone scrolls; everything above and below stays put.
    5. Foot: the usage Dash in a compact three-line form (Claude windows; Codex; Mac memory, CPU, GPU), each value tinted as today; then a row with Settings, the overnight moon (today's top bar control) and "More ▾" (Analytics, History, Guestbook).
  4. Folded strip signal. When folded, the strip shows one dot at its top: red if an agent is blocked, magenta if anything needs you (Inbox needs-you count > 0 or a Needs-you agent), otherwise none.
  5. Fold state is remembered per view kind in local storage sm-sidebar = { pages, terminal, doc }, each open|folded. Defaults: pages open at ≥1100 px else folded; terminal open at ≥900 px else folded; doc folded. First run migrates sm-layout.rail (full→open) into pages and sm-term-switcher into terminal.
  6. 720–900 px. The sidebar, when opened, overlays main (today's switcher overlay rule) and closes after a pick.
  7. ≤720 px (phone). Unchanged. List pages keep today's bottom tab bar (the same page items as today, Agents first); the terminal is full screen with today's phone bar and key row; the document view is full screen with a back arrow. No sidebar.
  8. Example: 1512×820 window, Board page, sm-sidebar.pages=open. Sidebar 15.5 rem; Board gets the rest. Clicking far-2390 navigates to /terminal/<far-2390 id>; the sidebar stays open because terminal=open; the row is highlighted.

E. Terminal view and kept connection

  1. Inside the terminal page, the old .term-side column (switcher and edge strip) is removed; the sidebar replaces it. Retire still moves to the next row by today's rowAfterRetire, computed on the sidebar's order.
  2. One kept terminal. App() holds kept = { id, leftAt }. Leaving a terminal view for any non-terminal view sets it. The TerminalPage for kept.id stays mounted with the same key inside a wrapper with the hidden attribute. Returning to /terminal/kept.id un-hides it. Opening a different terminal unmounts the kept one first with today's teardown.
  3. No resize while hidden. A hidden element measures 0×0; a resize from it would shrink the agent's real tmux window. While hidden the page runs no fit and sends no resize frame. On un-hide it fits once and sends one resize only if the size differs from the last one sent.
  4. Focus. On hide, the terminal is blurred, so keys typed elsewhere never reach the agent. On un-hide it takes focus.
  5. While hidden, output is written to the off-screen terminal, pings continue, reconnects proceed as today.
  6. After 15 minutes hidden the app unmounts it and clears kept; a timer, cleared on return. If the session stops or the connection reaches Ended while hidden, the same happens immediately.
  7. pagehide/pageshow handling is unchanged and covers the kept terminal.
  8. Tab title on a terminal view: <session name> · sm.

  3. Back. The ← button and ⌘[ do history.back() when the previous entry is in this app, else navigate to /. Because opening a document is a pushState, Back from a document reached from a terminal lands on that terminal, which is still connected (E.2).
  4. Z. FAQ

Why keep the Agents overview at all? It is the only place showing stopped agents, the By repo grouping, and per-agent facts side by side. Web request logs for the last two weeks show the terminal screen about four times as busy as the Agents page, so it is a secondary view, but not an empty one. If it stays unused after this ships, landing on the terminal of the agent that most needs you is a one-line change.

Why 15 minutes for the kept terminal? It covers a look at Board, Queue or a document and back, which is what the second tab is used for, without a forgotten terminal streaming over the Cloudflare relay all afternoon. It is a constant.

Why only one kept terminal? Moving between agents through the sidebar reconnects today and is not part of the complaint. Keeping several multiplies streams for little gain.

Why not put page links in a top bar? It frees width, but the terminal and document views need their bar for their own title and actions, so pages would need a second bar, costing two terminal rows on every screen.

Does the Android app change? No. It has native navigation and its own terminal and document screens.
