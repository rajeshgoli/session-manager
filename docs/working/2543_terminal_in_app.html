2543 — One app: the terminal, documents and pages share one frame

Author: Claude (Opus 5.5) 0ba7dfd9 · Ticket #2543 · 2026-10-27 · Revision 5

Memo

I recommend that the terminal page's layout become the layout of the whole web app. Every page gets one left sidebar. It holds the page links as today, the live agents and shells (the list that today exists only on the terminal page), compact usage meters, and Settings. On a terminal the sidebar puts agents first; on every other page it puts pages first. The Agents page becomes the overview behind the "Agents" heading. Documents open full width instead of in the side panel. The top bar shows only what you are looking at, with the moon and the bug button at its right end on every screen.

From a terminal, any page is one click away. From any page, any agent is one click away. ⌘[ returns to the terminal you just left, still connected.

Sidebar
The single left column on every page. From the top: "sm" and the search box (⌘K); the page links; the Agents heading and the live agents and shells; the usage meters; Settings. It folds to a thin strip with ⌘\ or a click on that strip.
Pages first, agents first
The sidebar's two arrangements. Pages first: every page link as today, and each agent on a one-line row. Agents first: page links as one row of icons, and each agent on today's two-line row. Pages first is the default on pages; agents first is the default on a terminal. The chevron after "10 live" swaps them.
Focus view
A page about one thing that wants the whole width: an agent's or shell's terminal, or a document.
Top bar
The bar above the main area. Left: what you are looking at. Right: actions on it, then the moon and the bug button.
Side panel
The resizable column on the right: an agent's details and message thread, a queue job, a ticket, Notes.

The screens

All six screens are drawn at the size of the window in your screenshots, 1512 × 820, with ten live agents. They use the app's own colours, fonts and icons.

What moves and what stays

  • Stays: every page link (Inbox, Board, Queue, Artifacts, Notes, Analytics, History, Guestbook), Settings at the bottom on its own, and the moon and bug button at the top right. The moon and bug button now also appear on the terminal and document bars.
  • Moves into the sidebar: search goes to the top. New agent becomes the + on the Agents heading. Queue status ("1 · 0") sits beside the Queue link.
  • Moves into the top bar: the Agents overview's counts and By repo / With stopped toggles, and the Notes page's "+ New".
  • Becomes smaller: the meters, from about 300 points to about 75 (Screen 6).
  • Moves out of the side panel: documents, which open full width (Screen 4).

How it flows: one evening

You are watching far-2390 in its terminal. The Inbox icon has a magenta dot. You click it and read far-2419's question. You click far-2419 in the sidebar; its terminal opens, and you answer. Its message links the iteration 11 memo. You click the link, and the memo fills the screen with the sidebar folded. ⌘[ takes you back to far-2419's terminal, still connected and up to date. You click Queue to see whether the backtest finished, then far-2390 in the sidebar. You never leave the tab, and the sidebar never moves.

Why this design

The terminal page already had the right layout. Its left column lists the agents, which is what you navigate by. Today's left column lists pages, and today's Agents page is a large version of the agents list. One column holding both gives one place to go anywhere. Slack and Linear use this layout for the same reason.

It fits, measured on your screenshots. A page link is 32 points, an agent's two-line row 48, its one-line row 26, a section heading 26.

  • Pages first takes about 730 of 820 points: search 40, eight page links 256, heading 34, ten one-line rows and group gaps 290, meters 75, Settings 36. The one-line rows drop the section headings; each dot's colour shows the section.
  • Agents first takes about 810: search 40, icon row 36, heading 34, ten two-line rows with headings 590, meters 75, Settings 36. Shells and anything past ten agents scroll.

The meters show only what you need to know. The server already computes each quota's pace: when it will run out, or what share it will reach at reset. A line under a provider appears only when a limit will run out before reset, or when most of the week will go unused. The Mac shows only readings that are already amber or red on today's scale; otherwise it says "quiet". sm does not measure disk today, so disk is not shown.

Focus views stay immersive. The terminal keeps today's width and bar. A document gets the full width, because the side panel is a poor place to read.

Cost. On Board and Queue the sidebar is wider than today's left column (15.5 rem against 9 rem, about 100 points), because it now holds agents. ⌘\ folds it on any page.

E. Terminal view and kept connection

  1. Inside the terminal page, the old .term-side column (switcher and edge strip) is removed; the sidebar replaces it. Retire still moves to the next row by today's rowAfterRetire, computed on the sidebar's order.
  2. One kept terminal. App() holds kept = { id, leftAt }. Leaving a terminal view for any non-terminal view sets it. The TerminalPage for kept.id stays mounted with the same key inside a wrapper with the hidden attribute. Returning to /terminal/kept.id un-hides it. Opening a different terminal unmounts the kept one first with today's teardown.
  3. No resize while hidden. A hidden element measures 0×0; a resize from it would shrink the agent's real tmux window. While hidden the page runs no fit and sends no resize frame. On un-hide it fits once and sends one resize only if the size differs from the last one sent.
  4. Focus. On hide, the terminal is blurred, so keys typed elsewhere never reach the agent. On un-hide it takes focus.
  5. While hidden, output is written to the off-screen terminal, pings continue, reconnects proceed as today.
  6. After 15 minutes hidden the app unmounts it and clears kept; a timer, cleared on return. If the session stops or the connection reaches Ended while hidden, the same happens immediately.
  7. pagehide/pageshow handling is unchanged and covers the kept terminal.
  8. Tab title on a terminal view: <session name> · sm.

Z. FAQ

How did the design get here? Revision 1 kept the page links as a narrow icon column beside the terminal's agents list; the owner found two left columns overloaded and bolted on, and it left the Agents page and documents unaddressed. Revision 2 merged both lists into one sidebar, made the Agents page the overview behind the heading, and moved documents out of the side panel; it did not fit at real sizes. Revision 3 makes the sidebar's parts take turns, sized on real screenshots for 8–10 agents. Revision 4 gives the top bar one rule (only about what you are looking at). Revision 5 keeps every page link, Settings and the moon where the owner has them, takes the room from compact, importance-based meters instead of a More menu, and shows the design as six screens. The separate "Terminal" page link and g t shortcut of revision 1 are gone: every agent is in the sidebar.

Why keep the Agents overview at all? It is the only place showing stopped agents, the By repo grouping, and per-agent facts side by side. Web request logs for the last two weeks show the terminal screen about four times as busy as the Agents page, so it is a secondary view, but not an empty one. If it stays unused after this ships, landing on the terminal of the agent that most needs you is a one-line change.

Why 15 minutes for the kept terminal? It covers a look at Board, Queue or a document and back, which is what the second tab is used for, without a forgotten terminal streaming over the Cloudflare relay all afternoon. It is a constant.

Why only one kept terminal? Moving between agents through the sidebar reconnects today and is not part of the complaint. Keeping several multiplies streams for little gain.

Why not put page links in a top bar? It frees width, but the terminal and document views need their bar for their own title and actions, so pages would need a second bar, costing two terminal rows on every screen.

Does the Android app change? No. It has native navigation and its own terminal and document screens.
