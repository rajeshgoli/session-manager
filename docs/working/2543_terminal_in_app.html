2543 — The terminal page joins the rest of sm

Author: Claude (Opus 5.5) 0ba7dfd9 · Ticket #2543 · 2026-10-27

Memo

I recommend keeping the terminal page exactly as immersive as it is, and giving it back the one thing it lacks: the app's left navigation. Today, opening a terminal hides the navigation column (Agents, Board, Inbox, Queue…), the top bar and ⌘K search, so the terminal behaves like a separate site that you enter and leave. That is why you keep it in its own browser tab. With the change below, the terminal is one more page in that column, Board and Queue are one click away from it, and a click on "Terminal" brings you back to the agent you were watching, still connected.

Four terms, used throughout:

Left navigation
The column on every sm web page except the terminal: Agents, Board, Inbox, Queue, Artifacts, Notes… with their red and amber count badges, and the usage meters (Claude 5-hour and weekly, Codex, Mac memory/CPU/GPU) at the bottom. Its narrow form shows only icons, dot badges and short meter readings, about 50 px wide.
Terminal page
The page at sm.rajeshgo.li/terminal/<id>: a live agent or shell terminal, its top bar (Notes, Details, Hand off…, Retire) and the session list.
Session list
The terminal page's own left column: live agents grouped Needs you / Moving / Idle, plus shells. ⌘\ folds it; ⌘⌥↑/↓ steps through it.
⌘K search
The "Search or jump…" box: pages, agents, tickets and docs by name.

What is wrong today

The two pages are already one web app sharing one stylesheet and one login. The split is a single deliberate choice in the code: when the address is a terminal, the app draws only the terminal page, and switches off ⌘K and the g-letter page jumps.1 Nothing about that choice is load-bearing. The terminal page's good qualities (full-height terminal, focused top bar, foldable session list) do not depend on hiding the navigation.

The change, in five parts

#What you getHow it behaves

It stays narrow there regardless of how you set it elsewhere, because the session list already takes the wide slot. Your ⌘\ habit is unchanged: on the terminal page it still folds the session list.

Your questions, answered

What of the Agents page is truly missing from the terminal page? Less than it looks. Everything about one agent (facts, jobs, reviews, PR links, its message thread and Send box) is already one click away under Details, which opens beside the terminal. What is genuinely missing is the cross-agent and cross-page context:

Missing on the terminal page todayAfter this change
Page navigation and its badges (Inbox needs-you count, Queue waiting, Board, Artifacts)Present: narrow left navigation (part 1).
Usage meters (Claude, Codex, Mac CPU/memory/GPU)Present: short readings at the foot of the narrow navigation, as on any page with it folded.
⌘K searchPresent (part 4).
"New agent" buttonReached by one click to Agents. I do not add it to the terminal top bar, which is full; say so if you start agents from the terminal often.
The Agents page's overview: "1 needs you · 2 moving", By repo, With stoppedStays on Agents. The session list already shows the same attention grouping.
Overnight moon and night bannerStays off the terminal page; not something you set mid-session.

Can the terminal's side rail become top or bottom bars? I recommend against it. Putting page links in the terminal's top bar costs no width, but then the navigation lives on the left on every page and at the top on one, which is the "different place" feeling we are removing. The narrow left column costs about six of roughly 200 terminal columns on your screen. A bottom bar would cost terminal rows, which matter more than columns for an agent's output.

Can the main page adopt the collapsible sidebar? It already folds: the small ‹ beside "sm" and ⌘\ narrow it to the icon form shown above. It is easy to miss next to the terminal page's full-height fold strip. I recommend the main pages use the same full-height strip on the navigation's right edge, so both columns fold the same way and the control is obvious. On the terminal page the navigation has no strip, since it is always narrow there.

What about the phone? No change. At phone width the navigation is a bottom tab bar, and the terminal page deliberately has none: the keyboard and the Esc/Tab/Ctrl-C key row already take the space. The Android app has its own navigation and is untouched.

B. Layout

  1. App() no longer returns early for the terminal page. It renders the normal .app grid with Rail in the first column and the terminal page in the second, with class term-mode on .app. On the terminal page it does not render TopBar, NightBanner or the right-hand Panel; the terminal page keeps its own top bar and its own Details/Notes column beside the terminal, as today.
  2. In term-mode the navigation is drawn folded (--rail-w: 3.2rem, the existing .folded rules) whatever sm-layout.rail says, and the saved sm-layout.rail value is not changed. Leaving the terminal page restores the saved form. The fold strip (F) is not drawn in term-mode.
  3. .term-page stops being position: fixed; inset: 0; z-index: 30. It fills its grid cell (height: 100%, flex column as now). Everything inside it (bar, session list, edge strip, body, side panels, notices, popovers anchored with position: fixed at top: 44px; right: 12px) keeps its current rules; the popovers' right anchor is unaffected because they hang from the right edge.
  4. Width 720 px and below: term-mode hides .rail (display: none) and the terminal page takes the full width, exactly as today. No bottom tab bar on the terminal page.
  5. Between 720 and 900 px: the narrow navigation shows; the session list keeps its existing overlay behaviour, which is positioned inside .term-main and so sits right of the navigation.
  6. Toasts, the bug dialog and the retire confirmation keep their current stacking; the navigation must sit below them (it has no z-index today, which suffices once .term-page is no longer a fixed overlay).

C. The Terminal page item and /terminal

  1. PAGES gains { key: 'terminal', label: 'Terminal', icon: 'terminal', path: '/terminal', key_hint: 't' } immediately after Agents. The terminal icon already exists in web/ui.js. No badge.
  2. pageFor returns 'terminal' for /terminal and /terminal/…. The item is highlighted (on, aria-current="page") on every terminal page.
  3. Remembering. Whenever the terminal page shows session X, the client stores X under local storage key sm-term-last (via store, so a blocked storage is harmless).
  4. Target. A click on the item, g t, the ⌘K "Terminal" page row, or arriving at bare /terminal resolves the target from the shared watch state (/watch/state sessions; fetch once if the shared copy is empty):
    1. sm-term-last if that session exists and is not stopped (hidden shells count: you opened it last);
    2. else the first row of switcherGroups(sessions, null, false).order, which is the first Needs-you agent, then Moving, and so on, never a hidden shell;
    3. else stay on, or go to, / and toast "No live agents or shells".
    It then navigates to /terminal/<id>. From bare /terminal it uses history.replaceState, so Back does not land on the bare address again. Clicking the item while already on a terminal page does nothing.
  5. Example: you open far-2390's terminal, go to Board, far-2390 is retired by its parent, you click Terminal. sm-term-last is far-2390, which is stopped, so the target is the top session-list row, far-2419-o-h3 (Needs you).
  6. Server: add .route("/terminal", get(web::get_shell_only_page)) beside the existing /terminal/{session_id} route in http.rs, so a reload or a typed sm.rajeshgo.li/terminal serves the app. Same owner check, same 404 on non-browser hosts.
  7. The ⌘K list shows "Terminal" as a Page row with detail g t, from pageItem unchanged.

E. Keeping the terminal connected

  1. One kept terminal. App() holds kept = { id, leftAt }. On leaving a terminal page for a non-terminal page, kept becomes that page's id and the time. The TerminalPage element for kept.id stays mounted (same Preact key, so its effect does not re-run), inside a wrapper with the hidden attribute, alongside the normal page. Returning to /terminal/kept.id un-hides it. Navigating to any other terminal id unmounts the kept one first (today's teardown: detach, close socket, dispose).
  2. No resize while hidden. This is the one hazard: a hidden element measures 0×0, and a resize sent from it would shrink the agent's real tmux window. While hidden, the page sends no resize frame and runs no fit. On un-hide it fits once and sends one resize if the size differs from the last one sent. The test in H.5 proves no resize frame leaves while hidden.
  3. Focus. On hide, the terminal is blurred, so keys typed on Board never reach the agent. On un-hide it is focused, as on a fresh open.
  4. While hidden output keeps arriving and is written to the off-screen terminal; pings continue; the connection label logic is unchanged. A reconnect triggered while hidden proceeds as normal.
  5. 15-minute limit. When the kept terminal has been hidden 15 minutes, the app unmounts it and clears kept. The next visit opens fresh. A timer, not a poll; cleared on return.
  6. Session ends while hidden. If the watch state shows it stopped, or the connection reaches Ended, unmount and clear kept. Retiring from the terminal page itself keeps today's behaviour (move to next row).
  7. Browser tab events. pagehide/pageshow handling is unchanged and applies to the kept terminal too.
  8. The Details or Notes column beside a kept terminal is part of the URL (?open=); returning via the Terminal item opens the bare /terminal/<id> (no column), and the terminal refits to the wider space on un-hide.

F. Navigation fold strip

The navigation's ‹/› fold button beside "sm" is replaced by a full-height 14 px strip on the navigation's right edge, drawn with the same rules as the terminal's .term-edge (border, hover colour, fold/unfold icon, title "Fold menu (⌘\)" / "Expand menu (⌘\)"). ⌘\ is unchanged. Not drawn at 720 px and below (bottom tab bar) or in term-mode. The strip adds 14 px to the navigation width in both forms, so --rail-w grows by that amount; the .app.wide .panel left offset follows --rail-w already.

  3. Bug reports filed from the terminal page keep page="Terminal".

Z. FAQ

Why not render the navigation inside TerminalPage? The navigation's badges and meters come from useRailData in App(); rendering the one Rail from App() keeps a single source and a single component.

Why 15 minutes? Long enough to cover a look at Board, Queue or a doc and back, the pattern the two-tab habit serves; short enough that a forgotten terminal does not stream output over the Cloudflare relay all afternoon. It is a constant; changing it later is one line.

Why only one kept terminal? Switching between agents goes through the session list, which reconnects today and is not part of the complaint. Keeping several would multiply streams for little gain.

Does this touch the Android app? No. Its terminal is a separate WebView page with native navigation around it.
