# Maintainer Lessons

Durable lessons from maintainer sessions. Read this before handling the maintainer queue, and append short high-signal lessons when a session uncovers something future maintainers should know.

## Current Lessons

- A loopback TCP response cannot attest which process owns the port. Destructive cross-repository recovery must use the queue authority Unix socket, bind the response to the kernel peer PID, require that PID to equal the in-process `SMJobCopyDictionary` result for the launchd label, and verify the live PID's installed executable path and code-sign identity before trusting queue fields. Self-reported labels, HTTP headers, `PATH`-resolved CLIs, and subprocess inspection are not authority.
- Treat `completion_status=killed` as a terminal lifecycle marker even if a stale status-only writer leaves `status=idle` or `running`. Live roster, hooks, routing, attach, reminders, and context surfaces must agree on that invariant; automatic tmux-client revival must skip killed records, and explicit restore is the only path that clears the terminal markers.
- Provider-native `/btw` runs in an isolated side conversation. Default `sm what` prompts must explicitly ask for the main conversation thread and exclude the `/btw` side conversation, or the summary can truthfully but uselessly report that no work happened.
- Cutover removal decisions must be revisited when live agent workflows prove a surface is still operationally required. Durable `sm remind --recurring` belongs in the Rust queue database and scheduler; launchd timers are not an acceptable substitute because they bypass session teardown, cancellation, restart recovery, and queue observability.
- Claude Code UI forks can create a new Session Manager session ID while continuing in the same tmux runtime. When that happens, inherited recurring reminders need to be self-identifying so the active fork can cancel them directly.
- The repo already supports generic file-driven service-role bootstrap via `service_roles.<role>.bootstrap_prompt_file` in `config.yaml`. Prefer that path over hard-coded prompt text when workflow instructions need to evolve.
- The maintainer role should prefer `codex-fork`, then `codex`, then `claude` by default. Keep the file-backed `service_roles.maintainer.preferred_providers` entry and the legacy maintainer fallback defaults aligned.
- The local PR review workflow doc lives at `~/.agent-os/workflows/pr_review_process.md`. Use that file for the Codex review / merge loop.
- Maintainer work is not done at PR creation. It is done only after review feedback is handled, the PR is merged, Session Manager is restarted on merged code, and the reporting agent has been notified of the fix.
- Use the reporting agent for missing repro/debug details sparingly. Ask only for specific facts you cannot recover from the running system or repository state.
- Session restore features only work if explicit kill paths preserve the stopped `Session` record instead of deleting it during cleanup. Restore also needs provider-native resume metadata captured while the session is alive, not reconstructed later from guesswork.
- `sm restore <identifier>` cannot reuse the generic session-name resolver when friendly names collide. Restore must prefer a stopped alias/friendly-name match and fail clearly on multiple stopped matches instead of targeting an arbitrary running session.
- Session restore cannot survive a reboot if `paths.state_file` points at `/tmp`. Keep the session registry on durable storage such as `~/.local/share/claude-sessions/sessions.json`, and migrate legacy temp-backed state before relying on restore after crash/OOM.
- Email bridge identity and user routing should stay file-driven in `config/email_send.yaml`, not hard-coded in Python. Keeping registered users, authorized inbound senders, and the webhook path in one gitignored file makes maintainer changes operational instead of code-only.
- A service cutover must inventory worker-facing public ingress, not only interactive app hosts. If a legacy hostname remains necessary for a webhook, require its exact path-scoped route in deployment preflight and keep every other path behind the terminal 404 catch-all.
- When Telegram is healthy but a specific agent is hard to find, check whether the topic was created before the effective display identity was known. Claude native titles can be discovered lazily from transcripts after topic creation, so the external display sync marker must be current before assuming routing is broken.
- List/readiness paths such as `/sessions`, `/client/sessions`, `sm all`, and `sm me` must not perform live display identity discovery or external sync. Use cached session identity there so stale tmux panes, transcript discovery, or Telegram topic drift cannot block the maintainer queue.
- Mobile attach readiness depends on both local `sm-android-sshd` and the public cloudflared tunnel. If Termux reports `websocket: bad handshake`, check `com.rajesh.sm-android-tunnel` before debugging tmux or app code.
- Telegram topic cleanup must treat `Topic_id_invalid` as already-cleaned remote state and tombstone the local registry record; otherwise one invalid topic can stay active and fail deletion forever.
- Codex app Telegram topics may have no tmux session name. Cleanup must decide whether those records are routable from the live Session Manager session, not from tmux existence alone.
- Live `sm send <friendly-name>` routing must beat registered-email fallback in every mode. When triaging reports about named agents going to email, verify against the running merged service first and keep regression coverage around the CLI resolver path.
- `sm send` should not reuse the generic 5s CLI API timeout. Real `/sessions/{id}/input` delivery can take longer under queue contention, and resolution timeouts must surface as unavailability instead of falling through to email fallback for live session IDs.
- tmux-backed Claude urgent delivery can preserve long-running work by sending a single `Ctrl+B`, waiting for the prompt, then sending `Escape` before injecting the urgent payload. Live `codex` and `codex-fork` probes did not show a reliable equivalent backgrounding path, so keep them on their native interrupt behavior until proven otherwise.
- After `gh pr merge`, wait for GitHub to finish the merge before pulling and restarting launchd. Pulling `main` too early can leave the local checkout behind the merged commit, and a "successful restart" on stale code does not satisfy maintainer completion.
- If a launchd-managed Session Manager restart still serves pre-merge server behavior even though the source tree and launchd path are correct, clear `src/__pycache__/server*.pyc` and kickstart again before assuming the merged server fix failed. Live verification showed stale bytecode could survive a fast restart path.
- Claude-native slash commands injected through Session Manager, such as `/rename`, must stay standalone queue deliveries. Sequential batching joins queued text with blank lines, which turns slash commands into plain prompt text and silently drops the intended control action.
- If orchestrators report `Session manager unavailable or request timed out` during heavy post-spawn mutation bursts, check whether the CLI path is still using the generic 5s timeout. In live investigation, the backend stayed healthy while mutation requests queued behind real work; the false outage was the short client timeout, not an explicit server-side rate limiter.
- Hook traffic can carry near-megabyte `PostToolUse` payloads. Keep hook JSON decoding and display-name work off the event-loop thread, or routine `sm` CLI calls will time out behind hook backpressure even when the server stays up.
- Do not point `codex_fork.command` at a checkout under `~/worktrees`. That location can disappear during unrelated cleanup. Keep the fork checkout/binary on durable storage such as `~/Desktop/automation/codex-fork` (or another non-transient path), and audit any operator docs/config that still assume the old worktree path.
- Do not await Telegram topic creation or welcome-message sends on restore/startup readiness paths. Those network calls can stretch `sm restore` into multi-second requests and keep the API unavailable during launchd recovery; defer them with the existing background topic helper instead.
- Explicit session restore should clear `agent_task_completed_at` along with other completion metadata. Otherwise a revived auto-bootstrapped service session can inherit stale `task-complete` state and get auto-retired again seconds later.
- Do not tombstone a Telegram forum topic locally until `deleteForumTopic` has actually succeeded. Marking closed topics as deleted before remote deletion completes makes the stale-topic sweeper skip them forever, which can leave thousands of closed topics in Telegram.
- Plain `codex` sessions can briefly report `status=idle` immediately after a Stop hook even while work is still active. List/watch surfaces need a short recent-activity grace window before projecting them inactive.
- Android/Termux attach readiness must verify the public `cloudflared access ssh` path, not just whether `com.rajesh.sm-android-tunnel` is running. A live tunnel process can still leave the public SSH route unhealthy and produce `websocket: bad handshake` or banner timeouts.
- Read surfaces that accept durable service-role identifiers should resolve live registry aliases such as `maintainer` before returning 404. Clients do treat `/sessions/maintainer` as a stable session reference even when the concrete session ID changes.
- Android-native watch fixes are not live when the PR merges unless `data/apps/session-manager-android/latest.apk` is rebuilt and redeployed. Check `data/apps/session-manager-android/meta.json` and the served artifact hash before telling users a mobile fix shipped.
- Android in-app terminal attach must stream a real PTY into a terminal emulator. Rendering `tmux capture-pane -e` snapshots as plain Compose text will expose ANSI escape/control bytes and cannot provide first-class Claude/Codex TUI behavior.
- Android in-app terminal attach failures like `Expected HTTP 101 response but was 404` mean the request reached `/client/terminal` without a successful WebSocket upgrade. Keep that path explicitly diagnosable and make the mobile client retry with a fresh signed ticket instead of requiring manual detach/reattach.
- Android in-app terminal scrollback needs both xterm gesture handling and a bounded one-time tmux history preload. The live PTY stream only contains output produced after attach; use `capture-pane -e -p -S <lines> -E -1` to seed retained pre-attach pane history before starting the live tmux attach.
- Claude Code focus-tracking warnings for SM-managed sessions should be fixed on the dedicated Session Manager tmux socket, not in global `~/.tmux.conf`. Enforce `focus-events on` through SM-owned tmux server options so manual tmux usage remains unaffected.
- tmux-backed plain `codex` sessions do not emit Claude Stop hooks. If monitor/timeout logic marks them `status=idle`, it must also reconcile `message_queue.delivery_states[session_id].is_idle`, or watch/mobile surfaces can keep showing stale thinking/working state with `pending_count=0`.
- Claude native `/rename` can update the pane title before transcript title metadata catches up, and sometimes without a useful transcript title at all. Keep cached Claude `native_title` refresh on a background path (not read APIs), and let live pane titles win when transcript metadata is missing or lagging so watch/list surfaces converge quickly.
- Claude spawn/create paths with an explicit friendly name need to enqueue the native `/rename` during session creation and keep immediate API responses on the explicit SM name. Otherwise the first prompt-derived Claude title can race ahead of a later `sm name` PATCH and temporarily overwrite watch/Telegram display identity.
- Fresh `codex-fork` create paths (`sm codex`, `sm codex-fork`, `sm spawn ... codex`) must fail clearly when the configured fork binary is unavailable. Do not silently downgrade them to plain `codex` after session identity allocation, or users will get `codex-fork-*` names backed by the wrong provider.
- Session-detail read paths must follow the same cached-identity rule as list/readiness paths. `GET /sessions/{id}` and `GET /sessions/{id}/children` must not lazily read Claude transcripts, update tmux titles, or rename Telegram topics just to answer `sm me` / `sm children`, or those reads can backlog the whole API under multi-agent load.
- `sm watch` terminal layout should size columns from row content before using static weights. In dense orchestrator views, short/blank columns such as Role and Last can otherwise hold padding while long Session names are truncated.
- Listing a retained command in the Rust CLI manifest is not a cutover gate. Execute each retained command through real dispatch before retiring its prior entry point; rich local Python TUIs may remain internal components behind Rust when flags, working directory, API selection, and operator gating are preserved.
- `PATCH /sessions/{id}` should use the same bounded Telegram display-sync timeout as lazy identity reconciliation. Friendly-name writes are operator-facing control-paths; a slow Telegram topic rename must degrade to a warning instead of consuming the full 5s CLI API timeout and surfacing as “Session manager unavailable.”
- Bounded display sync has to include tmux status-bar updates too, not just Telegram renames. Post-spawn `sm name` can still overrun the 5s CLI timeout if `_sync_session_display_identity()` awaits `tmux.set_status_bar(...)` unbounded, even when the backend itself is healthy.
- `sm request-codex-review list --all` only widens the notify-target scope; it still hides completed requests unless `--inactive` is passed. If a maintainer thinks a review wake was missed, check the delivered `[sm review]` rows in `message_queue.db` and retry with `--inactive` before assuming the watcher failed.
- Restore needs provider launch choices persisted on the Session record. A session spawned with explicit `--model` or `--effort` should replay both on `sm restore`; otherwise Claude/Codex may silently resume with different model behavior.
- Child-scoped destructive commands must carry `SESSION_MANAGER_ID` from the Rust CLI and enforce the direct-parent relationship in the server/store. A missing requester is reserved for deliberate operator-shell use; never let a managed CLI silently omit it, and never print success defaults for API error payloads.
- Codex `/rename` emits a structured `thread_name_updated` event and updates `~/.codex/session_index.jsonl`; sync those into cached `Session.native_title` for Codex providers instead of scraping ANSI pane output.
- Explicit SM names should be pushed into provider-native titles for both Claude and tmux-backed Codex. Keep `/rename` delivery as a standalone `native_rename` queue item so SM display, provider thread name, and Telegram/watch identity converge.
- After Codex 0.125, codex-fork control-socket message injection must submit external text through the TUI's normal `UserTurn` path. Sending deprecated `UserInput` ops can render "Not available in TUI yet for thread ..." and make `sm send` look delivered while the TUI rejects it.
- Do not run live tmux probes on the asyncio event loop or for ordinary stopped records during startup restore. Under large session registries and active `sm watch` clients, synchronous `session_exists`/pane capture calls can trip the watchdog and make every `sm` command time out.
- Startup constructors for durable stores must not run large retention sweeps before uvicorn binds. If a SQLite table can grow into hundreds of MB, create pruning indexes with the filtered column first and run initial prune/maintenance on a background path.
- Codex event-store overflow retention must stay bounded to recently written/pending sessions. A global `GROUP BY session_id HAVING COUNT(*)...` scan over a large `codex_events.db` can stall `/sessions` long enough for `sm all` and `sm watch` to report Session Manager unavailable.
- Codex tmux `/rename` is an interactive dialog, not a reliable single-line `/rename <name>` command. For `codex`/`codex-fork`, drive `/rename`, wait for the Name/Rename thread prompt, clear the field, then submit the safe name separately.
- SM-managed `codex-fork` launches should disable Codex's interactive startup update prompt. Session Manager owns fork update cadence, and a pinned runtime can legitimately be current even when a squash merge means the upstream release tag is not a Git ancestor.
- Provider-native rename sync is control-plane best effort, not user input. If the provider control socket or rename dialog fails, drop the queued `native_rename` instead of retrying forever into an active prompt.
- A tmux server process keeps the argv from the command that first created that socket. Do not treat `ps` rows like `tmux -L session-manager new-session -s <agent-id>` as orphaned agent processes; killing that PID kills every session on the socket. Keep the configured tmux socket anchored under a neutral SM session before spawning agents.
- Android Termux attach can fail with `websocket: bad handshake` even when the Mac-side Cloudflare tunnel and SSHD are healthy. Do not call `cloudflared access login` for a pure SSH tunnel hostname unless it is also a Cloudflare Access application login URL; prefer a direct LAN SSH fallback from the supervised `android_sshd` listener and surface Cloudflare tunnel diagnostics.
- After restarting Session Manager, verify the commit in `launchctl print ...`'s working directory, not just the shared checkout. If launchd points at a temporary worktree, that worktree must be fast-forwarded before restarting, or the service can report healthy while still running stale code.
- Do not register a launchd service against a path a build tool writes. The Rust server used to run straight out of `target/release/sm-server`, so every `cargo build` replaced the live binary under a running process, and any later failure left it one KeepAlive respawn away from an outage. It now runs from an installed copy at `.local/bin/sm-server`, written only while the job is booted out.
- Restart the Rust server with `scripts/restart-rust-server.sh` and nothing else. Do not hand-roll `cargo build` + `launchctl kickstart -k`: launchd can pin a launch constraint into the job registration, and a rebuilt binary then gets SIGKILLed at spawn with `CODESIGNING / Launch Constraint Violation`, which `KeepAlive` turns into a crash loop. Only re-registering the job (bootout -> bootstrap -> kickstart) clears it, and `kickstart -k` does not re-register. The script also keeps the dangerous ordering right, since build and signing must both succeed before anything stops the running service. See `specs/1134_rust_restart_procedure.md`.
- `./target/release/sm-server --help` exiting 0 does not prove launchd will accept the binary. A launch constraint is enforced by launchd at spawn, not by `exec`, so an exec smoke test is not a restart gate. Equally, one healthy `/health` response does not prove the service is up: with `KeepAlive`, a crash-looping service looks alive between respawns, so confirm the pid is unchanged over ~20s.
- A tmux `pipe-pane` log is a terminal event stream, not rendered screen text. TUI repaint traffic can turn a small line tail into thousands of cursor, title, and style sequences; operator-facing output must use `capture-pane` to render the pane first, trim blank viewport padding, and only then apply line bounds.
- Background usage scans must bound and reap every project-key `git rev-parse` child. A single pathological working directory can otherwise block all transcript checkpoints indefinitely while the HTTP service remains healthy, making deployment smoke tests look like ordinary first-scan warm-up.
- Incremental usage backfills must checkpoint in bounded transactions. Holding one SQLite write transaction for an entire artifact lets a large historical log starve live burn and identity writers past their freshness window, making an otherwise correct report degrade to `unknown`.
- A bounded transaction is not enough if every usage scan replays every historical quota window. Persist semantic window-completion checkpoints and query only unmapped ledger rows so no-change scans do no write work and leave SQLite writer slots available for live hooks.
- Hook contract tests must preserve provider-native JSON types. Claude status-line quota resets are Unix epoch numbers for subscriber usage payloads; string-only fixtures can hide a parser that silently drops every live window.
- Retaining a running session across a server restart is not enough when its provider state comes from a tailed event stream. Startup must recreate live monitors at the current stream end; historical scanners can backfill old events, but they cannot provide timely activity, context, or rate-limit telemetry.
- Codex context usage is FYI telemetry. Plain Codex, codex-fork, and codex-app manage compaction inline, so `sm context-monitor enable` must remain a no-op for those providers and must not queue warning, critical, handoff, or compaction prompts.
- Before implementation edits in a shared checkout, verify the active branch and worktree isolation. If the checkout is on an unrelated spec/review branch, preserve the diff, move it to a main-based branch or worktree, and clean only your own tracked edits from the shared checkout before continuing.
- If an agent reports a lost long handoff sent as `cat ... | sm send <target> -`, check the queued message body. Older builds treated `-` as a literal message while still reporting success; fixed builds should read piped stdin or fail clearly on empty/interactive stdin.
- Android watch activity indicators must use the shared operational-activity classifier rather than comparing projected labels with only `running` or `active`. Live agents commonly project `working`, `thinking`, or waiting states, and literal label checks render those sessions as inactive.
- Android tail fallbacks must request `/sessions/{id}/output?rendered=true` and still strip terminal controls client-side. The default output is a terminal event stream, so bounding it before rendering can expose ANSI repaint traffic instead of readable tail text.
- Do not height-cap a Markdown `TextView` inside the Android watch `LazyColumn` and rely on its scrollbar. `TextView` does not participate in Compose nested scrolling here, so the parent consumes gestures and clips the document; measure the Markdown at full height and let the watch list own vertical scrolling.
- Tree promotion must distinguish recorded lineage from live authority. Keep a stopped source-parent edge as a stale-write precondition, but never copy that stopped ancestor onto the promoted target or gate the live-tree move on repeated human approval.
- Do not add `sm watch-job` after `sm queue run`. Native queue jobs are already durable and automatically wake their notify target on completion; terminal wakes retry idempotently until durably queued, then runtime reconciliation retries until delivered. Start supervised commands through the queue instead of trying to register an existing PID afterward.
- A durable completion message is not a delivered completion wake. Background producers must also trigger runtime queue reconciliation, preserve FIFO ordering, and keep busy targets pending until the provider is writable.
- A queue wrapper PID is not the job lifecycle. Timeout, cancellation, terminal state, and capacity release must account the persisted process group; an exited wrapper can leave descendants performing signal cleanup. Application-owned locks still require application-owned recovery.
- Before attributing a queue-job death to perf displacement, compare persisted timestamps and workload types. Perf displacement is restricted to `background`; a `tests` job that ended before the cited perf submission has an external or unknown cause, regardless of how plausible cross-epic contention appears.
